What is FLAIR-GG?

One network for genetic resources, with each bank's data kept at its source.

FLAIR-GG began by making the César Gómez Campo Banco de Germoplasma Vegetal (BGV-UPM) FAIR. It now links germplasm collections across Spain with the wider ecosystem of taxonomic, conservation and molecular resources. Data never has to be pooled centrally: every member publishes its own standards-based description, and the network does the rest.

Findable by design

Every bank describes itself, its collections and its services in DCAT, published from its own FAIR Data Point. A central index harvests these descriptions, so a new member becomes searchable as soon as it registers.

A shared data model

Passport data is expressed with an ontology based on the FAO Multi-Crop Passport Descriptors. Banks export plain CSV from whatever system they already use, and the toolkit turns it into linked data.

Federated, not centralised

Because every bank uses the same model, one query can go to all sites at once. Each bank stays the authoritative, up-to-date source for its own records and decides what it shares.

The Virtual Platform

Ask the whole network a question, then analyse the answers.

The FLAIR-GG Virtual Platform (VP) is the shared portal on top of the network. It works only from the live index, so anything a member publishes appears without central curation.

Open the VP → Analysis notebooks
  • Network-wide searchKeyword and ontology-term search across every bank's catalogues, datasets and services.
  • Federated data servicesRun one service type, for example collecting-site coordinates by species or IUCN categorisation, against every provider in a single call.
  • Results straight into analysisService results open in the FLAIR-GG Analytics Jupyter notebooks, which run in the browser with nothing to install.
  • Built for scaleTested with 3,700 datasets, more than the number of germplasm banks on Earth.
AI-ready infrastructure

AI assistants can query the network directly.

The Virtual Platform runs a Model Context Protocol (MCP) server, the open standard that lets AI assistants such as Claude call external tools. A researcher can ask a question in plain language. The assistant then queries the live FLAIR-GG network itself and answers from authoritative, up-to-date records, not from what it remembers.

keyword_search

Finds catalogues, datasets and services anywhere in the network whose metadata mentions a term, using the same search that drives the VP's own interface.

sparql_query Experimental

Read-only SPARQL over the FDP Index for questions a keyword can't answer: counting, grouping, filtering, and "who curates this collection, and how do I contact them?"

iucn_endangerment_status

Runs the IUCN Red List categorisation service against every live provider and returns each provider's results, so the assistant can compare conservation status across banks.

Designed to grow with the network

  • One tool per service type. Every provider of a given service type implements the same interface, so one tool covers them all, and adding a provider requires no change to the tool.
  • Providers are discovered live. Tools find their providers through the VP's own service discovery each time they run, so new and relocated banks are picked up automatically.
  • Grounded in curated analyses. Each service-type tool points the assistant to the reference Jupyter notebook for that data, so it reproduces the established analysis instead of inventing its own.
  • Native to the platform. The protocol is implemented directly in the VP's own codebase, with each tool defined in a single file. Adding a tool is a small, reviewable change.
